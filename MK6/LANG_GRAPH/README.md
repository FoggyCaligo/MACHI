# MK6 LANG_GRAPH

## 목적

`LANG_GRAPH`는 문장을 일반적인 "단어 토큰"으로 먼저 자르는 계층이 아니다.  
먼저 입력을 **글자 흐름 자체**로 저장하고, 그 위에 반복 입력의 중첩이 쌓이면서  
나중에 segment가 떠오르도록 만드는 **독립 그래프 계층**이다.

`LANG_GRAPH`와 `CONCEPT_GRAPH`는 같은 그래프의 두 모드가 아니다.  
둘은 **서로 다른 그래프**다.

- `LANG_GRAPH`: 글자 흐름과 segment 형성을 다루는 그래프
- `CONCEPT_GRAPH`: `LANG_GRAPH`가 넘긴 segment 리스트를 받아 기억과 사고를 다루는 그래프

이 계층의 목표는 다음과 같다.

- 입력 문장을 공백과 문장부호까지 포함한 `alph` 흐름으로 저장한다.
- 한 번의 입력을 하나의 `input_id`를 가진 독립 경로로 저장한다.
- 기존 경로와 겹치는 부분이 많을수록, 이후 입력에서 그 구간이 더 강한 segment 후보가 되게 한다.
- 이렇게 얻은 segment 리스트를 **다른 그래프인** `CONCEPT_GRAPH`에 넘긴다.

---

## 핵심 비유

이 설계는 "셀로판지 겹침" 비유를 따른다.

- `"엄마"`가 입력되면 `엄 -> 마`를 잇는 옅은 셀로판지 한 장이 놓인다.
- 다음에 `"엄마가 분유 타줄게"`가 입력되면 `엄 -> 마 -> 가 -> ...` 경로를 잇는 또 다른 셀로판지가 놓인다.
- 그다음 `"엄마는 내일 출장가"`가 들어오면, 현재 입력의 순서와 맞지 않는 예전 경로는 이번 해석에서는 걷어내고, 현재 입력과 순서가 맞는 경로들만 겹쳐서 본다.
- 그러면 `엄마`처럼 반복적으로 살아남는 구간은 더 진하게 보이고, 단독 글자나 약한 구간은 상대적으로 흐리게 보인다.

즉, `LANG_GRAPH`는 사전 기반으로 "이게 단어다"를 먼저 정하는 구조가 아니라  
**입력 이력의 중첩으로 단어 같은 묶음이 떠오르게 하는 구조**다.

## 용어

### `alph`

- 입력을 이루는 최소 단위 글자
- 한글, 영문, 숫자뿐 아니라 공백과 문장부호도 포함한다
- 예:
  - `"엄마"` -> `["엄", "마"]`
  - `"엄마가."` -> `["엄", "마", "가", "."]`
  - `"a b"` -> `["a", " ", "b"]`

### `seq`

- 한 입력 안에서 `alph`들이 순서대로 이어진 경로
- `input_id` 하나당 하나의 경로 묶음이 생긴다
- 같은 `엄 -> 마`라도 입력이 다르면 같은 에지를 재사용하는 것이 아니라 **새 기록**으로 추가된다

### `segment`

- 현재 입력을 해석할 때, 과거 경로와의 겹침 때문에 상대적으로 선명하게 드러나는 묶음
- `엄마`, `아이`, `엄마가`처럼 길이가 2 이상인 구간이 먼저 강한 후보가 된다
- 필요하면 단일 글자도 결과에 남을 수 있다

### `input_id`

- 한 번의 입력 전체를 식별하는 고유 ID
- 같은 입력에서 생성된 모든 `seq` 에지는 동일한 `input_id`를 가진다

## 처리 흐름

### 1. 입력 수신

사용자가 문장 또는 단어를 입력한다.

예:

```text
엄마가 아이를 안는다.
```

### 2. `alph` 분해

입력을 공백과 문장부호를 포함해서 한 글자씩 분해한다.

```text
["엄", "마", "가", " ", "아", "이", "를", " ", "안", "는", "다", "."]
```

### 3. 현재 그래프 기준 segment 탐색

이번 입력을 아직 저장하기 전에, 기존 `LANG_GRAPH` 안에서  
현재 입력의 부분 문자열 중 어떤 구간이 과거 입력들과 많이 겹치는지 본다.

예를 들어 과거에 아래 입력들이 있었다고 하자.

```text
엄마
엄마의 아이
아이
```

그러면 `"엄마가 아이를 안는다."`를 볼 때:

- `"엄마"`는 과거 경로와 잘 겹친다
- `"아이"`도 과거 경로와 잘 겹친다
- `"엄마가"`는 `"엄마"`보다 약할 수 있지만 후보가 될 수 있다
- 처음 보는 나머지 부분은 단일 글자 fallback이 될 수 있다

결과 예시는 다음처럼 될 수 있다.

```python
["엄마", "가", " ", "아이", "를", " ", "안", "는", "다", "."]
```

이 값이 바로 다른 그래프인 `CONCEPT_GRAPH`에 넘겨질 segment 리스트다.

### 4. 새 입력 저장

segment 탐색이 끝나면, 이번 입력 자체를 새로운 `input_id`로 저장한다.

- 각 `alph`를 노드 테이블에 등록
- 각 인접 글자 쌍을 `seq_edges`에 저장
- 같은 문자 경로가 과거에 있었어도 이번 입력의 기록은 새로 남김

즉, 저장은 누적이고, 해석은 현재 입력 기준 필터링이다.

---

## 중요한 설계 원칙

### 1. 공백과 문장부호도 동일한 글자다

공백과 문장부호를 별도 전처리로 지우지 않는다.

이유:

- 새로운 문장부호 습관도 학습 대상이다
- `"엄마가"`와 `"엄마 가"`는 다른 경로다
- `"안녕."`과 `"안녕!"`도 다른 경로다

### 2. 에지는 재활용보다 기록 누적이 우선이다

예전에 `엄 -> 마`가 있었어도 이번 입력에서 다시 나오면 새 기록이 생긴다.

즉:

- "굵기를 직접 증가시키는 단일 에지" 모델이 아니라
- "같은 위치에 셀로판지 한 장을 더 올리는" 모델이다

### 3. 현재 입력과 맞지 않는 경로는 이번 해석에서 걷어낸다

이 원칙이 없으면:

- `"엄마"` 때문에 `"엄청"`의 `엄`이 잘못 강해질 수 있다
- `"마작"` 같은 unrelated 연결이 끼어들 수 있다

따라서 segment 판단은 단순 글자 빈도가 아니라  
**현재 입력 내부의 연속 순서와 맞는 경로만 남겨서** 해야 한다.

### 4. 단어는 사전에서 오지 않는다

`LANG_GRAPH` 안의 단어성은 형태소 사전이나 품사 규칙에서 오지 않는다.

단어 비슷한 묶음은:

- 반복 입력
- 현재 입력과의 순서 일치
- 중첩 강도

이 세 가지에서 떠오른다.

## `CONCEPT_GRAPH`와의 관계

`LANG_GRAPH`와 `CONCEPT_GRAPH`는 역할이 이어질 뿐, 내부 저장 구조는 분리된다.

흐름은 다음과 같다.

1. 사용자 입력이 `LANG_GRAPH`에 들어간다.
2. `LANG_GRAPH`는 입력을 `alph` 경로로 저장하고, 그 이력 위에서 segment 리스트를 뽑는다.
3. `CONCEPT_GRAPH`는 그 **segment 리스트 결과만 입력으로 받는다.**
4. 그다음부터의 기억, 정정, 최신성, 연결, 사고는 `CONCEPT_GRAPH` 내부 규칙으로 처리한다.

중요한 점:

- `CONCEPT_GRAPH`는 `LANG_GRAPH`의 글자 에지를 그대로 쓰지 않는다.
- `LANG_GRAPH`의 `alph`, `seq`, `input_id` 구조와 `CONCEPT_GRAPH`의 개념 구조는 분리된다.
- `CONCEPT_GRAPH`는 "`LANG_GRAPH`가 잘라서 넘긴 결과"를 사용한다.

즉:

```text
사용자 입력
  -> LANG_GRAPH
  -> segment list
  -> CONCEPT_GRAPH
```

이지,

```text
사용자 입력
  -> 하나의 그래프 안에서 언어 단계와 개념 단계가 섞여서 처리
```

가 아니다.

## 현재 API

### import 방식

```python
from MK6.LANG_GRAPH import segment_text

segments = segment_text("엄마가 아이를 안는다.")
print(segments)
```

또는:

```python
from MK6.LANG_GRAPH import LanguageGraph

graph = LanguageGraph()
segments = graph.segment_text("엄마가 아이를 안는다.")
graph.close()
```

### 터미널 테스트 명령

`LANG_GRAPH` 내부에서 바로 실행해서 결과를 볼 수 있다.

```powershell
python -m MK6.LANG_GRAPH.run_lang_graph "엄마가 아이를 안는다."
```

문장을 인자로 생략하면 직접 입력받는다.

```powershell
python -m MK6.LANG_GRAPH.run_lang_graph
```

### 반환값

- 타입: `list[str]`
- 의미: 현재 그래프 이력을 기준으로 잘린 segment 목록

예:

```python
["엄마", "가", " ", "아이", "를", " ", "안", "는", "다", "."]
```

## DB 구조

### `alph_nodes`

- `alph TEXT PRIMARY KEY`
- `created_at TEXT`

의미:

- 그래프에 등장한 개별 글자 집합

### `seq_edges`

- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `input_id TEXT`
- `position INTEGER`
- `source_alph TEXT`
- `target_alph TEXT`
- `created_at TEXT`

의미:

- 한 입력 안에서 인접한 글자 간의 방향 에지
- 같은 `source_alph -> target_alph`라도 입력이 다르면 별도 행으로 저장

## 향후 확장 방향

### 1. 경로 기반 필터링 강화

부분문자열 카운트가 아니라, 현재 입력 전체 경로와 일치하는 과거 `input_id` 레이어만 남겨서  
segment 후보를 고르는 방식으로 바꿔야 한다.

### 2. 후보 점수 구조화

단순 count가 아니라:

- 길이
- 반복 횟수
- 최근성
- 현재 입력과의 정렬 일치도

를 분리해서 점수화할 수 있다.

### 3. 반환 계약 확장

나중에는 단순 `list[str]`만이 아니라:

```python
[
    {
        "segment": "엄마",
        "score": 7.2,
        "source_inputs": ["input-1", "input-4"],
        "start": 0,
        "end": 2,
    }
]
```

같은 형태가 필요할 수 있다.

### 4. `CONCEPT_GRAPH`와의 연결

다른 그래프인 `CONCEPT_GRAPH`는 이 segment 리스트를 받아:

- 어떤 segment를 개념 노드로 쓸지
- 조사나 어미를 어떻게 다룰지
- 최신 정정을 어떻게 반영할지

를 결정하는 상위 계층이 된다.

즉, `LANG_GRAPH`는 "생각"보다 앞 단계의 언어 표면 구조 형성기이고,  
`CONCEPT_GRAPH`는 그 결과를 넘겨받아 따로 작동하는 개념 그래프다.
