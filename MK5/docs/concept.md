# MK5 Concept

## 1. 문서의 목적

이 문서는 `MK5`가 그래프 중심 구조를 어떻게 실제 동작 경로로 정제하는지 설명한다.

핵심 질문은 아래와 같다.

- 왜 `MK5`의 구조만으로는 실사용 경로가 아직 흔들릴 수 있는가
- 왜 검색 결과를 문장 참고가 아니라 그래프 재료로 다뤄야 하는가
- 왜 correction을 cue string보다 주장 구조로 보아야 하는가
- 왜 표면형 병합을 늦춰야 하는가

## 2. 출발 문제

`MK5`는 언어와 의미 그래프를 분리하고, 해시 주소를 통해 그래프에 접근하는 구조를 세웠다. 하지만 실제 대화 루프에서는 아직 아래 문제가 남는다.

- 검색 결과가 그래프 안에서 일관되게 흡수되지 않을 수 있다.
- correction이 표면 문구에 과하게 의존할 수 있다.
- 비슷한 표면형을 너무 빨리 합치면 잘못된 병합이 생길 수 있다.

## 3. MK5의 핵심 방향

`MK5`는 구조 자체를 갈아엎기보다, 아래처럼 운영 원칙을 더 보수적으로 다듬는다.

1. 검색 결과도 다시 그래프 경로를 거치게 한다.
2. correction은 assertion 구조 비교로 본다.
3. alias는 evidence를 충분히 모은 뒤에야 merge 한다.
4. 최종 언어화에서는 input / conclusion / search의 역할을 분리한다.

## 4. 검색 결과의 그래프화

검색 결과는 단순 스니펫이 아니다.

- 결과 텍스트를 다시 그래프에 연결한다.
- 현재 그래프와 bridge edge로 이어 붙인다.
- 필요한 경우 장기 그래프 반영 후보로 삼는다.

즉 검색은 외부 문장을 읽는 행위가 아니라, **현재 그래프를 확장하는 재료를 가져오는 행위**다.

## 5. correction의 구조화

`MK5`는 correction을 단어 신호보다 주장 구조의 변화로 본다.

- 지금 사용자 주장이 무엇인지
- 직전 주장과 무엇이 충돌하는지
- 같은 subject가 다른 object를 가리키는지

이 비교를 통해 correction과 conflict를 더 구조적으로 처리한다.

## 6. 지연 병합

표면형이 비슷하다고 바로 같은 노드가 되면 그래프는 쉽게 오염된다. 그래서 `MK5`는:

- 우선 별도 노드로 유지하고
- `surface_variant_evidence`를 모으고
- 구조적 근거가 충분할 때만 `concept_merge`를 허용한다

이 방식을 택한다.

## 7. 요약

`MK5`는 기존 그래프 철학을 유지하면서, **검색 통합, correction 처리, alias 병합 타이밍**을 더 안정적으로 만드는 정제 단계다.
