# MK5 — Graph-first Thinking Research

`MK5`는 MACHI의 **그래프 자체가 사고를 진행하는 구조**를 연구하는 세대입니다.

중요한 점은 현재 프로젝트의 역할 구분입니다.

- **현재 실제로 계속 사용·개선하는 실행형 MACHI:** `MK4`
- **장기적으로 발전시키려는 graph-first thinking 방법론:** `MK5`

MK5에는 실제로 동작하는 과거 프로토타입 코드가 존재하지만, 이 README는 앞으로 **"그래프 자체가 기억뿐 아니라 사고까지 담당하려면 어떤 구조가 필요한가"**를 정리하는 연구 문서의 역할을 맡습니다.

따라서 아래 내용에는 이미 시험해 본 구조와 아직 장기적으로 발전시켜야 하는 아이디어가 함께 포함되어 있습니다. 여기 적힌 내용을 MK4의 현재 구현 기능으로 해석하지 않습니다.

---

## 1. 문제의식

현재 MK4에서는 LLM이 응답 계획과 도구 선택, 최종 문장 생성을 담당하고 그래프는 장기 기억과 회수를 지원합니다.

이 구조는 현실적으로 잘 작동하지만, MACHI의 더 장기적인 질문은 남아 있습니다.

> **LLM이 모든 사고 과정을 담당하지 않고, 그래프의 구조와 활성화 자체가 사고를 진행하도록 만들 수 있는가?**

MK5는 이 질문을 다룹니다.

---

## 2. 목표

MK5가 지향하는 최종 구조는 다음과 같습니다.

> 언어는 그래프에 접근하고 결과를 표현하기 위한 입출력 계층으로 두고, 실제 기억·맥락·목적·사고·결론 형성은 의미 그래프의 구조 변화와 활성화 안에서 수행한다.

이를 위해 다음 문제를 해결하려 합니다.

- 같은 개념이 다른 단어라는 이유만으로 다른 의미가 되는 문제
- 언어 표면형이 사고 구조 자체를 지배하는 문제
- LLM 내부의 숨겨진 상태에만 사고 과정을 의존하는 문제
- 기억과 현재 사고가 별개의 시스템으로 분리되는 문제
- 판단 과정을 사람이 직접 읽거나 수정하기 어려운 문제

---

## 3. 핵심 방향

### 3.1 언어와 의미 그래프의 분리

단어는 의미 그 자체가 아니라 **의미 그래프에 접근하기 위한 표면 주소**로 취급합니다.

```text
언어 표현
    ↓
표면형 / 주소 계층
    ↓
의미 노드
    ↓
의미 그래프
```

같은 의미를 여러 표현이 가리킬 수 있고, 하나의 표현 역시 문맥에 따라 여러 의미 후보를 가질 수 있어야 합니다.

과거 MK5 프로토타입에서는 이를 위해 `surface_form`, `address_hash`, `words`, `nodes` 등을 분리해 시험했습니다.

이 구현은 최종 정답이라기보다 **언어와 의미를 분리하기 위한 첫 실험**으로 봅니다.

---

### 3.2 영구 기억 그래프와 현재 사고 공간의 분리

장기 기억 전체를 매 턴 직접 수정하면서 사고하면 기억이 쉽게 흔들릴 수 있습니다.

그래서 MK5에서는 다음 두 공간을 구분합니다.

```text
WorldGraph
장기적으로 축적된 기억과 개념 구조

        ↓ 필요한 부분 활성화 / 회수

TempThoughtGraph
현재 턴에서만 사용하는 임시 사고 공간
```

현재 입력 때문에 잠시 만들어진 가설이나 연결은 우선 임시 공간에서 다루고, 충분한 근거가 있는 변화만 장기 그래프에 반영하는 것이 목표입니다.

---

### 3.3 목적(goal)을 사고의 기준점으로 사용

사고는 단순히 현재 입력에서 주변 노드로 퍼지는 과정만으로는 부족합니다.

MACHI가 무엇을 해결하려고 하는지 나타내는 **goal**을 함께 두고,

```text
현재 입력
    ↘
      임시 사고 그래프 ↔ 관련 기억
    ↗
  goal
```

현재 입력, 과거 기억, 사용자 상태가 goal과 어떤 관계를 가지는지를 그래프 구조 안에서 비교합니다.

과거 MK5 프로토타입에서는 goal node, `TempThoughtGraph`, `goal_alignment` 등을 이용해 이 방향을 시험했습니다.

---

### 3.4 그래프의 구조 자체가 사고 상태를 표현

장기적으로 가장 중요한 목표입니다.

가능하면 별도의 거대한 규칙표나 프롬프트가 아니라,

- 어떤 노드가 활성화되어 있는지
- 어떤 관계가 반복해서 지지되는지
- 어떤 관계가 서로 충돌하는지
- 현재 goal과 어떤 구조가 가까운지
- 어떤 개념들이 동시에 작업 공간에 들어와 있는지

같은 **그래프 자체의 상태가 곧 현재 사고 상태**가 되도록 만듭니다.

즉 숫자를 계산한 뒤 의미를 따로 부여하는 것이 아니라, 가능한 범위에서는 **구조를 보면 이미 그 의미가 드러나는 시스템**을 지향합니다.

---

## 4. 목표 사고 흐름

장기적으로 생각하는 흐름은 대략 다음과 같습니다.

```text
사용자 입력
↓
언어 표현을 의미 그래프 주소로 변환
↓
현재 입력과 관련된 기억 영역 활성화
↓
goal / 사용자 맥락 / 이전 사고 상태와 함께
임시 사고 공간 구성
↓
관련 개념과 관계 활성화
↓
충돌, 지지, 반복, 연결을 구조적으로 반영
↓
사고 공간 안에서 결론 후보 구조 형성
↓
가장 적합한 결론 구조 선택
↓
필요한 기억 변화만 장기 그래프에 반영
↓
결론 그래프를 언어로 표현
```

이 흐름 전체를 현재 MK4가 구현하고 있다는 뜻은 아닙니다.

**MK4에서는 현재 LLM이 사고와 계획의 본체이고, MK5는 이 역할을 장기적으로 그래프 쪽으로 이동시키기 위한 연구 방향입니다.**

---

## 5. 과거 MK5 프로토타입에서 구현해 본 것

현재 폴더의 코드는 완전히 비어 있는 미래 설계 문서가 아닙니다. 다음 아이디어는 실제 프로토타입으로 시험했습니다.

- 언어 표면형과 의미 노드의 분리
- `surface_form` → `address_hash` 기반 접근
- `WorldGraph`
- `LocalSubgraph`
- `TempThoughtGraph`
- goal node
- 현재 입력과 goal 연결
- 관련 기억 subgraph 회수
- concept differentiation
- surface variant evidence
- concept merge
- goal alignment
- activation 기반 conclusion graph
- graph → language 변환 흐름

대표적인 과거 흐름은 다음과 같았습니다.

```text
사용자 입력
-> 단어 정규화
-> address_hash 계산
-> 후보 의미 노드 접근
-> 관련 LocalSubgraph 구성
-> TempThoughtGraph 구성
-> goal과 입력·기억 연결
-> 그래프 구조 반복 조정
-> activation / goal alignment 기반 결론 구성
-> 필요한 변화만 WorldGraph 반영
-> ConclusionGraph
-> GraphToLang
```

이 프로토타입은 graph-first thinking의 가능성을 시험하는 데 의미가 있었지만, 실제 대화 시스템의 기본 실행 경로로 사용하기에는 파이프라인이 복잡하고 무거워지는 문제가 있었습니다.

그 결과 현재 실행형 시스템은 MK4에서 더 단순한 구조를 선택했습니다.

## 6. 아직 해결해야 할 것

MK5 방향을 실제 MACHI의 사고 본체로 발전시키려면 아직 해결해야 할 문제가 많습니다.

### 의미 노드는 어떻게 만들어지는가?

문자열 해시만으로는 진짜 의미 동일성을 결정할 수 없습니다. 표면형과 실제 개념의 관계를 어떻게 학습하고 수정할지 더 발전시켜야 합니다.

### 활성화는 무엇을 의미하는가?

단순 점수가 아니라, 반복·최근성·문맥·목적·충돌 등을 그래프 구조 안에서 어떻게 자연스럽게 나타낼지 정해야 합니다.

### 그래프는 어떻게 새로운 관계를 발견하는가?

이미 저장된 edge를 따라가는 것만으로는 사고라 부르기 어렵습니다. 서로 떨어져 있던 개념을 현재 작업 공간에서 비교하고 새로운 연결 후보를 만드는 과정이 필요합니다.

### 언제 장기 기억을 수정하는가?

현재 턴에서 만들어진 가설을 즉시 진실로 저장하면 안 됩니다. 반복, 근거, source, contradiction을 이용해 영구 그래프 수정 조건을 정해야 합니다.

### 언제 사고를 끝내는가?

goal alignment 하나만으로 충분한지, 결론 구조의 안정성이나 추가 탐색의 기대 이득까지 볼 것인지 검토해야 합니다.

### LLM은 어디까지 남길 것인가?

장기 목표가 graph-first라고 해도 LLM을 완전히 제거해야 하는 것은 아닙니다.

가능한 역할은 다음과 같습니다.

- 자연어 → 그래프 입력 보조
- 모호한 개념 후보 생성
- 외부 지식 해석
- 그래프 결론 → 자연어 변환

중요한 것은 **핵심 사고 상태와 장기 기억의 주도권을 어디에 둘 것인가**입니다.

## 7. MK4와의 관계

MK5와 MK4는 경쟁 버전이라기보다 역할이 다릅니다.

### MK4

**현재 사용할 수 있는 MACHI.**

```text
LLM
├─ 응답 계획
├─ 도구 선택
└─ 최종 답변

Graph
├─ 장기 기억
├─ 사용자 모델
└─ 관련 기억 회수
```

### MK5 방향

**장기적으로 연구하는 MACHI.**

```text
Language / LLM
├─ 입력 해석 보조
└─ 출력 언어화

Graph
├─ 장기 기억
├─ 현재 작업 기억
├─ 관계 활성화
├─ 사고 진행
└─ 결론 구조 형성
```

따라서 당분간은 MK4를 충분히 오래 사용하면서 실제 실패 사례를 모으고, **MK4에서 반복적으로 나타나는 한계를 MK5 연구 방향이 정말 해결할 수 있는지 검증하는 방식**으로 발전시키는 것이 목표입니다.

## 8. 과거 프로토타입 실행

MK5의 기존 코드를 직접 확인하려면 다음과 같이 실행할 수 있습니다.

```powershell
git clone https://github.com/FoggyCaligo/MACHI.git
cd MACHI\MK5

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt

ollama serve
```

별도 PowerShell에서:

```powershell
ollama pull gemma3:4b
ollama pull nomic-embed-text
```

서버:

```powershell
python run_server.py --host 127.0.0.1 --port 8000 --reload
```

CLI:

```powershell
python run_cli.py
```

과거 구현을 볼 때 주요 파일은 다음과 같습니다.

- `core/utils/hash_resolver.py`
- `core/storage/world_graph.py`
- `core/translation/lang_to_graph.py`
- `core/thinking/temp_thought_graph.py`
- `core/thinking/thought_engine.py`
- `docs/architecture/graph_schema.md`

## 한 문장으로 요약하면

MK5는 **현재 완성된 MACHI를 설명하는 문서가 아니라, 장기적으로 LLM 중심 사고를 넘어 그래프의 구조와 활성화 자체가 기억·사고·결론을 만들어내도록 하기 위한 연구 축**입니다.
