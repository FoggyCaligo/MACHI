# MK2

`MK2`는 로컬 LLM이 사용자를 단순히 "조금 기억하는 수준"을 넘어서,  
**사용자라는 사람에 대한 인상을 이해하고, 기억하고, 나중에 갱신할 수 있게 만드는 단계**입니다.

`MK2`가 해결하고자 하는 문제는 다음과 같습니다.

- 기억이 조금 있어도, 그게 사용자를 하나의 사람으로 이해하는 수준까지 가지 못함
- 저장된 정보가 흩어져 있어서 "이 사용자는 어떤 사람인가"가 잘 형성되지 않음
- 한 번 만든 사용자 이해가 틀렸을 때, 그 이해를 다시 고치고 갱신하기 어려움

즉 `MK2`의 핵심 목표는,

> AI가 사용자를 하나의 모델처럼 이해하고, 그 이해를 기억으로 유지하고, 틀리면 다시 수정할 수 있게 만드는 것

입니다.

쉽게 말하면 `MK2`는 단순한 메모장이 아니라,  
**사용자에 대한 인상을 계속 다듬어 가는 기억 장치**입니다.

## 목표

`MK2`의 목표는 아래처럼 정리할 수 있습니다.

1. 사용자를 여러 조각 정보의 덩어리가 아니라, 하나의 사람으로 이해하기
2. 그 이해를 대화가 끝난 뒤에도 유지하기
3. 새로운 대화나 자료가 들어오면 기존 이해를 갱신하기
4. 잘못 이해한 부분이 드러나면 이전 기억을 수정하기
5. 다음 대화에서 그 사용자 모델을 다시 꺼내 답변에 반영하기

중요한 점은, `MK2`의 목적이 "기억을 많이 쌓는 것" 자체는 아니라는 것입니다.  
핵심은 **기억을 이용해 사용자 모델을 만들고, 그 모델을 계속 손보는 것**입니다.

## 기능

`MK2`는 크게 다섯 가지 일을 합니다.

### 1. 사용자에 대한 단서를 모읍니다

사용자가 말한 내용, 올린 텍스트, 프로젝트 자료 안에서  
"이 사람을 이해하는 데 도움이 되는 정보"를 찾습니다.

예를 들면 이런 것들입니다.

- 어떤 방식으로 생각하는지
- 무엇을 중요하게 여기는지
- 어떤 말투와 설명 방식을 선호하는지
- 최근 어떤 상황에 놓여 있는지
- 반복해서 드러나는 취향이나 성향이 무엇인지

여기서 중요한 것은, `MK2`가 이 단서들을 그냥 쌓아 두기만 하지는 않는다는 점입니다.

### 2. 단서를 사용자 프로필 후보로 바꿉니다

찾아낸 단서는 바로 "이 사람은 이런 사람이다"라고 확정되지 않습니다.  
먼저 프로필 후보로 들어갑니다.

이 단계는 성급한 오판을 줄이기 위한 장치입니다.

예를 들어 사용자가 한 번 어떤 취향을 말했다고 해서,
그걸 곧바로 고정된 성향으로 판단하지는 않습니다.

대신 `MK2`는

- 일단 후보로 두고
- 비슷한 근거가 더 들어오는지 보고
- 이미 있는 이해와 맞는지 비교한 뒤
- 점점 더 믿을 수 있는 사용자 이해로 올립니다

이런 식으로 움직입니다.

### 3. 사용자에 대한 이해를 기억으로 유지합니다

어느 정도 근거가 쌓이면, 그 내용은 단순 후보를 넘어  
사용자 프로필 기억으로 저장됩니다.

이 프로필 기억에는 예를 들어 이런 내용이 들어갈 수 있습니다.

- 이 사용자는 어떤 설명 방식을 좋아하는가
- 어떤 주제에 반복적으로 관심을 보이는가
- 어떤 작업 습관을 갖고 있는가
- 현재 어떤 프로젝트나 고민을 중심에 두고 있는가

즉 `MK2`는 단편 메모를 저장하는 것이 아니라,  
**사용자를 설명하는 문장들**을 조금씩 쌓아 가는 구조입니다.

### 4. 틀린 이해를 고칠 수 있습니다

이 부분이 `MK2`에서 특히 중요합니다.

사람을 이해하려고 들면, 처음에는 틀릴 수 있습니다.  
그래서 `MK2`는 한 번 만든 프로필을 절대적인 정답으로 취급하지 않습니다.

사용자가 나중에 이렇게 말할 수 있습니다.

- "나는 그런 스타일 아니야"
- "그건 예전 이야기고, 지금은 달라"
- "내 의도는 그게 아니라 이거였어"

이런 경우 `MK2`는 정정 정보를 따로 기록하고,  
이전 이해보다 더 우선해서 반영하려고 합니다.

즉 `MK2`의 사용자 모델은 고정된 초상화가 아니라,  
**계속 수정 가능한 초안**입니다.

### 5. 다음 대화에서 그 사용자 모델을 다시 꺼냅니다

새 대화가 시작되면 `MK2`는 지금 질문과 관련 있는 기억을 다시 찾습니다.

그 과정에서 다음 같은 정보가 검토됩니다.

- 현재 활성화된 사용자 프로필
- 아직 확정되지 않은 후보 프로필
- 최근 정정 내용
- 현재 상태 정보
- 관련 사건이나 요약

그 뒤에 답변을 만들기 때문에, AI는 단순히 "이번 메시지 하나"만 보는 것이 아니라  
**이 사용자가 어떤 사람인지에 대한 누적된 이해**를 참고할 수 있습니다.

## 작동 방식

개발을 모르는 사람 기준으로 보면, `MK2`는 아래 순서로 움직입니다.

```text
사용자가 말하거나 자료를 준다
-> 시스템이 그 안에서 사용자에 대한 단서를 찾는다
-> 단서를 프로필 후보로 정리한다
-> 기존 사용자 이해와 비교한다
-> 맞으면 강화하고, 틀리면 정정한다
-> 지금 대화와 관련 있는 사용자 모델을 다시 꺼낸다
-> 그 이해를 바탕으로 답변한다
```

조금 더 풀면 이렇습니다.

1. 사용자가 메시지를 보냅니다.
2. 시스템은 그 안에서 사용자 성향이나 상태와 관련된 단서를 뽑습니다.
3. 그 단서를 후보 기억으로 넣습니다.
4. 예전에 저장된 사용자 프로필과 비교합니다.
5. 새 근거가 충분하면 기존 프로필을 강화하거나 새로 만듭니다.
6. 반대로 사용자가 바로잡으면 정정 정보를 기록합니다.
7. 이후 답변을 만들 때 관련 프로필과 정정을 같이 참고합니다.

즉 `MK2`는 단순히 "기억한다"기보다,

- 사용자를 해석하고
- 그 해석을 프로필로 만들고
- 나중에 다시 고치고
- 답변에 재사용하는

구조라고 볼 수 있습니다.

## 기억 구조

`MK2`의 기억은 "문장을 그냥 저장하는 곳"이 아닙니다.  
사용자 모델을 만들기 위해 역할이 나뉜 여러 층으로 구성됩니다.

### 1. 원문 기록

사용자가 실제로 한 말이나 제공한 자료의 내용이 남습니다.  
이건 나중에 "왜 이런 이해가 생겼는가"를 추적하기 위한 바탕입니다.

### 2. 근거(evidence)

원문에서 뽑아낸 사용자 관련 단서가 따로 저장됩니다.  
아직 최종 결론은 아니고, 프로필을 만들기 위한 재료입니다.

예를 들어:

- 특정 방식의 설명을 선호한다
- 특정 주제에 반복적으로 관심을 보인다
- 최근 어떤 작업을 오래 붙잡고 있다

같은 단서가 여기에 들어갑니다.

### 3. 후보 프로필

근거는 먼저 후보 프로필이 됩니다.  
이 단계는 "맞을 가능성은 있지만 아직 확정하기 이른 이해"를 담는 곳입니다.

덕분에 `MK2`는 섣불리 사용자를 단정하지 않고,  
조금 더 조심스럽게 사용자 모델을 키워 갑니다.

### 4. 확정 프로필

여러 근거가 같은 방향을 가리키거나, 신뢰도가 충분하다고 판단되면  
후보 프로필은 더 강한 사용자 프로필 기억으로 올라갑니다.

이 층이 실제로 "이 사용자는 어떤 사람인가"를 설명하는 핵심 기억입니다.

### 5. 정정 기억

기존 프로필이 틀렸거나 오래되었을 때는 정정 정보가 따로 저장됩니다.  
이 구조 덕분에 `MK2`는 예전 이해를 무조건 유지하지 않고,  
더 최신의 이해로 사용자 모델을 바꿔 갈 수 있습니다.

### 6. 상태와 에피소드

사용자의 성향만 기억하는 것은 아닙니다.

- 지금 바쁜지
- 최근 어떤 프로젝트를 붙들고 있는지
- 최근 무슨 사건이 있었는지

같은 현재 상태와 사건도 따로 다룹니다.

그래서 `MK2`는

- "이 사용자는 원래 어떤 사람인가"
- "이 사용자는 지금 어떤 상황인가"

를 어느 정도 분리해서 기억하려고 합니다.

## 왜 이런 구조를 썼는가

`MK2`가 해결하려던 문제는 단순한 망각이 아니라,  
**사용자 이해가 구조화되지 않는 문제**였습니다.

기억이 조금 있더라도,

- 그 기억이 흩어져 있으면 사용자 인상이 형성되지 않고
- 잘못된 이해를 고칠 수 없으면 오해가 누적되고
- 다음 대화에서 어떤 기억을 꺼내야 할지도 모호해집니다

그래서 `MK2`는 기억을 단순 보관소가 아니라,

- 사용자 모델을 만드는 곳
- 그 모델을 검토하는 곳
- 틀렸을 때 수정하는 곳

으로 설계했습니다.

한 줄로 줄이면 `MK2`는

> "사용자를 기억하는 AI"에서 한 단계 더 나아가,  
> "사용자라는 사람에 대한 인상을 형성하고 갱신하는 AI"를 만들기 위한 시도

입니다.

## 실행 방법

아래 순서는 Windows 기준입니다.  
깨끗한 PC에서 시작한다고 가정하고, 그대로 따라 하면 저장소를 받고 실행할 수 있게 적었습니다.

### 1. Git 설치

Git이 없다면 먼저 설치합니다.

- 다운로드: [https://git-scm.com/download/win](https://git-scm.com/download/win)

설치 후 PowerShell을 엽니다.

### 2. 저장소 내려받기

```powershell
git clone https://github.com/FoggyCaligo/MACHI.git
cd MACHI\MK2
```

### 3. Python 설치

Python이 없다면 설치합니다.

- 다운로드: [https://www.python.org/downloads/windows/](https://www.python.org/downloads/windows/)

설치할 때 `Add Python to PATH` 옵션을 켜 두는 것이 좋습니다.

설치 후 확인:

```powershell
python --version
```

### 4. 가상환경 만들기

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

정상이라면 PowerShell 줄 앞에 `(.venv)`가 붙습니다.

### 5. 필요한 패키지 설치

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 6. Ollama 설치

이 프로젝트는 로컬 모델 실행에 Ollama를 사용합니다.

- 다운로드: [https://ollama.com/download](https://ollama.com/download)

설치 후 PowerShell에서 Ollama 서버를 실행합니다.

```powershell
ollama serve
```

다른 PowerShell 창을 하나 더 열고 기본 모델을 내려받습니다.

```powershell
ollama pull qwen2.5:3b
```

### 7. 서버 실행

`MK2` 폴더에서 아래 명령어를 실행합니다.

```powershell
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000 --reload
```

### 8. 브라우저에서 접속

브라우저 주소창에 아래를 입력합니다.

```text
http://127.0.0.1:8000/
```

정상 실행되면 채팅 화면이 열립니다.

**사용자에 대한 인상을 프로필 형태로 만들고, 그 이해를 기억하며, 틀리면 갱신할 수 있게 만드는 단계**입니다.
